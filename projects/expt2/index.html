n = document length, m = pattern length. Rabin-Karp's average case assumes few hash collisions; every collision needs a character-by-character check, which can push the worst case to O(nm).

About the Algorithms

Naive Search

Slides the pattern over the text one position at a time and checks, character by character, whether it matches at that position. Simple to write, but repeats comparisons when text has similar substrings.

  • Time: O(n·m) worst case
  • Space: O(1)
KMP (Knuth–Morris–Pratt)

Pre-processes the pattern into an LPS array (Longest Prefix that is also a Suffix). When a mismatch happens, the LPS array tells the algorithm how far it can safely skip ahead instead of restarting from scratch.

  • LPS array: for each prefix of the pattern, stores the length of the longest proper prefix that's also a suffix
  • Time: O(n + m)
  • Space: O(m) for the LPS array
Rabin-Karp

Computes a hash of the pattern and of each window of text using a rolling hash, which updates in O(1) when the window slides. If the hashes match, it double-checks the actual characters (to rule out a hash collision) before confirming a match.

  • Rolling hash: reuses the previous window's hash to compute the next one quickly
  • Verification: a matching hash still triggers a direct character comparison
  • Time: O(n + m) average, O(n·m) worst case (many collisions)
  • Space: O(1)
